# 0.8 phase 2 — the contract between the engine, the service and the window

Phase 2 adds the missing features users notice in their first week (from
[the competitor review](../reviews/2026-10/competitors.md), §2 items 1–3, 4, 10, 12, 13, 15, 16) and
splits Options into a simple view and *Advanced settings*. Three streams work in parallel: the
engine and service, the window, and the extension. This file fixes the names and shapes they
share, so each can be built and tested alone. If something here turns out to be wrong, change it
here in the same commit as the code, and say why in the DEVLOG.

Everything new is optional on the wire (`#[serde(default)]`, `Option` in patches), so a 0.7
settings file or list loads unchanged, and an older window talking to a newer service (or the
reverse) degrades instead of failing.

## Settings (`GET/POST /api/settings`, engine `Settings` / `SettingsPatch`)

| Field | Type | Default | Simple or Advanced | Meaning |
|---|---|---|---|---|
| `performance` | `"light" \| "balanced" \| "maximum" \| "custom"` | `"balanced"` | Simple (Downloads) | A preset. Setting it to anything but `custom` writes the knobs below in the same patch; changing any knob it owns turns it to `custom`. A knob given in the same patch as a preset wins (and so makes it `custom` unless it equals the preset's). `custom` chosen explicitly stays `custom`. A settings file from before presets reads as the preset its numbers match, else `custom`. `GET` also returns `profiles`, the table below, so the window needn't copy it. |
| `connections` | int 1–32 | 8 | Advanced | (exists) connections per download. Owned by `performance`. |
| `max_concurrent` | int 1–64 | 4 | Simple | (exists) downloads at the same time. Owned by `performance`. |
| `write_buffer_kib` | int 64–4096 | 256 | Advanced | Per-connection buffer before a write. Owned by `performance`. |
| `retries` | int 0–99 (0 = forever) | 5 | Advanced | Retries per connection without progress. |
| `retry_wait_secs` | int 1–600 | 3 | Advanced | First wait between retries; doubles up to 60 s (or the first wait, when that is longer). |
| `idle_timeout_secs` | int 10–3600 | 60 | Advanced | Give up on a connection that sends nothing for this long. |
| `connect_timeout_secs` | int 5–300 | 30 | Advanced | Give up on a server that doesn't answer. |
| `proxy` | object, below | `{"mode":"system"}` | Simple (Network) | |
| `keep_awake` | bool | true | Simple (General) | Hold a sleep inhibitor while any download transfers (not while only seeding), released 30 s after the last. Linux: a `systemd-inhibit --what=sleep --mode=block … cat` child (it ends when reIDM's end of its stdin closes, so it can't outlive a crash); macOS: `caffeinate -i -w <pid>`; Windows: a thread holding `SetThreadExecutionState(ES_CONTINUOUS \| ES_SYSTEM_REQUIRED)` (it belongs to the calling thread). Automatic sleep only; the display may still sleep. |
| `keep_awake_seeding` | bool | false | Advanced | …also while seeding. |
| `min_free_space_mib` | int ≥ 0 | 200 | Advanced | Stop a download (status note, auto-resume) before the destination or temporary folder would drop below this. |

Profiles (the engine owns this table, `Performance::apply`):

| | light | balanced | maximum |
|---|---|---|---|
| `connections` | 4 | 8 | 16 |
| `max_concurrent` | 2 | 4 | 8 |
| `write_buffer_kib` | 64 | 256 | 1024 |
| torrent peers per torrent (librqbit `peer_limit`, next session start) | 40 | 100 | 200 |

`custom` has no peer number of its own and uses balanced's (100).

`proxy`:
```json
{"mode": "system" | "none" | "manual",
 "kind": "http" | "https" | "socks5",      // manual only
 "host": "proxy.lan", "port": 3128,        // manual only
 "username": "u", "password": "p",         // optional; password is write-only: GET returns "password_set": true instead
 "bypass": ["*.lan", "10.0.0.0/8"],        // manual only
 "remote_dns": true,                       // socks5h; Advanced
 "torrents": false,                        // SOCKS5 only (librqbit); Advanced; next session start
 "videos": true}                           // pass --proxy to yt-dlp; Advanced
```
`system` = reqwest's environment/system proxy detection; `none` = `no_proxy()`. A change rebuilds
the HTTP client; running downloads pick it up on their next connection. In a `POST`, a `proxy`
without `password` keeps the stored one and `"password": ""` removes it; `GET` adds
`"password_set"`. A manual proxy needs a host (a name or address only: letters, digits, `.-_:[]`)
and a port, else the change is refused whole. `bypass` entries are reqwest `NoProxy` entries; a
leading `*.` is read as `.` (the domain and every name under it). yt-dlp gets the proxy as
`--proxy` in a `--config-locations` file written 0600 and removed after the run, never on its
command line (other users can read command lines); `none` with `videos` passes `--proxy ""`
(direct). Torrents need `kind: socks5` and `torrents: true`. Page scans (`/api/grab`) use the
proxy too; the update check does not yet.

## Downloads

- **Queue order.** `Item.order: u64` (persisted; on load, missing values are assigned in id order).
  The queue starts the queued download with the lowest `order`. `POST /api/downloads/{id}/move`
  with `{"to": "top" | "up" | "down" | "bottom"}`; `POST /api/downloads/bulk` accepts the same as
  `{"action": "move", "to": …, "ids": […]}` (moving a block keeps its internal order). Rows carry `order`.
  `up`/`down` move past the next download *not finished* (finished ones never wait in the queue, so
  stepping over them is what the user sees move); `top`/`bottom` go before/after every download.
  Orders start at 2³² so *top* has room below; only downloads whose place changes are written.
- **Checksums.** `Request.checksum: {"algo": "md5" | "sha1" | "sha256" | "sha512", "value": "hex"}`
  (optional; accepted by `POST /api/downloads`, `/ext/add`, `reidm add --checksum sha256:…`).
  Verified after the move into place, off the runtime; a mismatch is
  `Failed("checksum mismatch: expected …, got …")` (followed by where the file is kept and what to
  do) and the file is kept. Resuming such a download hashes the file again instead of fetching it
  (the expected value may have been wrong); restarting it downloads it again over its own file.
  The value is checked (hex of the algorithm's length) and kept in lower case; a video or a torrent
  given one is refused. `POST /api/downloads/{id}/verify {"algo": "sha256"}` (`algo` defaults to
  sha256) → `{"algo","value"}` for a finished download, or one that failed its checksum
  (computed on demand, for Properties' *Integrity* row). Rows carry `checksum_ok: true | false | null`.
- **Not enough space.** Before starting or resuming, and at each checkpoint, if what remains won't
  fit above `min_free_space_mib` on the temporary or destination volume: the download stops with
  status `Paused` and note `not enough space on <volume>: needs X, Y free` and `Item.waiting_for_space
  = true`; the scheduler retries such downloads every 30 s and resumes them when there is room.
  `GET /api/status` gains `free_space: [{"path": "...", "free": bytes}]` for the download folder
  and the temporary folder (for the status bar).
  *What remains* is, per drive: on the temporary folder's, the part file's size less what is
  allocated to it (Unix `st_blocks`; so a Linux part file reserved with `fallocate` needs nothing
  more), or less what is written (Windows); on the download folder's, nothing when it is the same
  drive (a rename), the whole size when it isn't (the final copy). Torrents write straight into
  their folder; videos into their work folder in the temporary folder. An unknown size counts as
  one byte. A drive is only "short" when it still needs a positive amount: a download whose
  space is reserved is never paused for space. HTTP downloads check at start, after the probe and
  with each 3 s checkpoint; videos and torrents every 10 s. The note reads `not enough space on
  <folder>: needs X more, Y free (reIDM keeps Z free; it carries on by itself when there is room)`.
  The 30 s retry starts waiting downloads in queue order, counting each against its drive's free
  space. Pausing a waiting download clears `waiting_for_space` (it then waits for the user);
  resuming it checks at once. `free` is `null` when a folder's drive can't be read.
- **Mark-of-the-Web for every output.** Videos (each file yt-dlp leaves) and torrents (each file,
  on completion) get the same mark HTTP downloads already get.

## When everything is done (not persisted — like qBittorrent, it resets each session)

- `GET /api/when-done` → `{"action": "none" | "exit" | "sleep" | "hibernate" | "shutdown",
  "fires_at": null | unix_secs}`; `POST /api/when-done {"action": …}` sets it; `POST
  /api/when-done/cancel` cancels a running countdown (and sets `none`).
- When the action isn't `none` and nothing is running or queued (paused, failed and seeding don't
  count), the service starts a 60 s countdown (`fires_at`), visible in `/api/status` as `when_done`.
  *Changed:* only once something has run since the action was chosen — choosing "shut down" with
  nothing to do must not shut the computer down a minute later. The action happens once and then
  reads `none`.
  Anything starting again cancels the countdown (but keeps the action). At the end: `exit` stops the
  service and asks the window to quit (status `exiting: true` for 6 s, then the service stops as on
  `POST /api/shutdown`); `sleep`/`hibernate`/`shutdown` call the OS (Windows
  `SetSuspendState`/`ExitWindowsEx` after enabling `SeShutdownPrivilege`, macOS `pmset sleepnow` —
  also for hibernate, which macOS does by itself when `hibernatemode` says so — / `osascript … shut
  down`, Linux logind over `systemctl suspend|hibernate|poweroff`), after flushing the list. A
  failed action is logged and added to `/api/status` `warnings`.
- CLI: `reidm when-done <action>`.

## Service internals the window relies on

- **Changed ids.** The engine records, per revision, which item ids changed
  (`Manager::changed_since(rev) -> Option<Vec<u64>>`, `None` when that revision is too old), so the
  row cache re-serialises only those (today it re-serialises all 50,000 to find one).
  Running downloads are always included (their progress moves the revision without a record).
  The record keeps the last 65,536 ids. `Manager::get_many(ids)` reads them under one lock.
- **Refresh address (extension M14).** `GET /ext/ping` gains `"refresh_armed": {"id", "name"} |
  null`. `refresh_address` probes and checks the new address *before* stopping the download, and
  leaves it untouched when the check fails. (After stopping it checks once more, since the first
  bytes may have arrived meanwhile; if that fails, the download is resumed as it was.)
- **`/ext/add` `refresh_id: u64`** (added for extension 1.7.0): the link is that download's new
  address. If that download is no longer armed, or the link is not the same file, the answer is a
  refusal (`400`, `{"ok": false, "error"}`) — never a new download, so a held browser download stays
  with the browser. The refresh stays armed after a wrong link.
- **`/ext/add` `no_refresh: true`**: don't try the link against the armed download at all, and leave
  it armed (an armed download never probed has no size, so it would accept any link).
- **Idempotent `/ext/add` (extension M19).** Optional `request_id` (string ≤ 64); the service
  remembers answers for 10 minutes and answers a repeat with the first answer. A repeat that
  arrives while the first request is still being checked waits for its answer (a shared
  `OnceCell` per id; if the first caller goes away part way, the next does the work). Refusals
  are answers too. At most 4,096 answers are kept (the oldest go first). With none of
  `request_id`, `refresh_id`, `no_refresh`, `/ext/add` behaves as before.
- **Saving a long list** (not a contract, but it decides the service's cost): debounced saves wait
  up to 25× the last save's duration (2–30 s) for more changes; urgent saves (adds, removals,
  status changes, flush) never wait.

## The window (gui.json, not the service)

- `advanced_settings: bool` (false) — shows the Advanced tab in Options.
- `tray: bool` (true), `close_to_tray: bool` (true), `minimize_to_tray: bool` (false, Advanced),
  `tray_notified: bool` (one-time "still running in the tray" note).
- `on_finish: "dialog" | "notification" | "nothing"` ("notification" when the tray works, else
  "dialog"); `notify_failures: bool` (true, Advanced).
- `watch_clipboard: bool` (false).
- Drag and drop: URLs/text → Add URL prefilled; `.torrent` → Add torrent; `.txt`/`.ef2` → Import.

Options' simple tabs: **General** (start with the computer, tray, keep awake, when a download
finishes, clipboard, language placeholder), **Folders** (as now), **Downloads** (performance,
downloads at the same time, speed limit, ask/start silently), **Network** (proxy), **Torrents**
(ratio, upload limit). An **Advanced settings** checkbox at the bottom-left reveals an *Advanced*
tab: a name | value | unit | ↺ grid of every Advanced field above plus connections, port, DHT,
temporary folder, with "requires restart" said in the label where it applies.
